# Kickoff prompt for Claude Code on the Windows PC: build the Unity stage

Status: written 2026-11-01. This is the next real step of the Unity route ([docs/UNITY.md](../../docs/UNITY.md)): everything that can be done without Unity is done and tested; what is left needs the Unity Editor, a GPU and a screen, so it runs on your PC. Nothing in the prompt has been run.

The cloud session cannot reach your PC or Unity's downloads. A Claude Code session on the PC can: it has the repository, the Unity CLI, and (once `com.unity.pipeline` is in the project) a live line into the open Editor.

Zero-paste alternative: in the Claude desktop app, enable Remote Control for the repository folder (Settings, Claude Code, Remote Control) and ask the cloud session to run these steps there; you only approve prompts. No PC folder was shared when this was written, so that needs the one setting first, and it has not been tried with Unity.

How to start by pasting: open PowerShell, then

```powershell
git clone --branch claude/determined-pasteur-klc0fw https://github.com/drakedreper/ai_assistant.git C:\dev\ai_assistant
cd C:\dev\ai_assistant
claude
```

(or `git pull` in your existing clone) and paste the prompt. Have ready: a **VRM 1.0 model of an adult character** you are allowed to use (a VRoid Studio export is fine), and Docker Desktop or Node 22.14+ with pnpm for the backend.

````text
You are building the Unity stage of a project on THIS Windows 11 PC (RTX 5070 Ti). The backend and an engine-free C# client already exist and are tested without Unity. Your job is the part that needs Unity: a Unity 6 project that connects to the backend, loads a VRM character into a dark "cerebral void" room, and lets her speak with a moving mouth. Report plainly. Do not claim anything works unless you saw it work; say "not verified" otherwise. Keep your own output short: tables and numbers, not narration.

REPO: this folder, branch claude/determined-pasteur-klc0fw. Read, in this order: CLAUDE.md, docs/UNITY.md, docs/DOCKER.md, docs/adr/0008-stage-protocol-and-engine-choice.md, docs/CEREBRAL-SPACE.md, packages/shared/src/stage.ts (the contract), and the C# package unity/Packages/com.mira.stage (Runtime/*.cs, Tests~/Tests/*.cs).

RULES
1. Ask before ANY step that changes this machine beyond the repo folder, and wait for my explicit yes: installing the Unity CLI, an Editor or UniVRM (downloads), starting Docker, copying a model, creating files outside the repo, pushing. Tell me what it changes first. Signing in to Unity (unity auth login) and activating a licence I do myself: tell me the exact command and wait.
2. The stage token is a secret. Never write it into a file, a scene, a ScriptableObject, a log or your replies. It reaches Unity only through the environment variable MIRA_STAGE_TOKEN of the process that starts Unity (or the Editor), or, on a native daemon, from the daemon's own secrets.json that StageCredentialsResolver already reads.
3. Never commit a binary model, texture or audio file (unity/.gitignore blocks *.vrm, *.glb, *.fbx and others on purpose). The models live in the content folder MIRA_CONTENT_DIR (default %USERPROFILE%\Mira\content), outside the repo. Use only an ADULT character model with a licence that allows this use; if you cannot tell, ask me.
4. Work on a new branch: git switch -c unity-stage-pc. Commit small, explained commits of text and C# only. Do NOT push; ask me first.
5. When a live Unity Editor is reachable (unity status shows state "ready"), drive it with unity command / unity command eval instead of hand-editing .unity, .prefab or .asset files. If the Editor is stuck in Safe Mode (C# compile errors), unity pipeline list shows it: fix the compile errors first. Never pass -batchmode or -quit to unity run. Use -h on any unity command instead of guessing flags or ids (module ids, template ids).
6. Do not weaken the invariants in CLAUDE.md (loopback only, no secrets in files or logs, all characters adults, clothed baseline). Do not change the contract (packages/shared/src/stage.ts) or the daemon unless a real defect forces it: report it and stop.
7. Results (screenshots, logs, RESULTS.md) go to spikes/unity/results/, which is git-ignored (spikes/.gitignore); never commit them. Do not edit the repo docs with your findings without my yes.

STEPS (in order; stop on a failed step, give the exact command and error text, your diagnosis, and ask)
0. Preconditions, report only: versions of git, node (needs >= 22.14), pnpm (10), docker, dotnet; unity --version and unity auth status / unity license status (if the CLI is missing, propose the install from the Unity CLI docs and wait for my yes); the GPU name and driver.
1. Backend. Ask which: Docker (start-docker.cmd, then print the token with the command in docs/DOCKER.md) or native (start.cmd). Check Settings, Stage is on and no other stage is connected. Show me how you will hand the token to Unity without writing it down.
2. Unity Editor. unity releases --stream lts --limit 3, then propose installing the latest LTS (Unity 6, 6000.x), no extra modules, and wait for my yes. Then unity templates list for that editor and propose the 3D URP template by the id the list shows. Create the project: unity projects create MiraStage --path unity --editor-version <version> --template <id>. Add the package to unity/MiraStage/Packages/manifest.json as "com.mira.stage": "file:../../Packages/com.mira.stage" (the relative path is from the project's Packages folder to unity/Packages/com.mira.stage; if Unity cannot resolve it, use Package Manager, Add package from disk, and let Unity write the path it wants). Unity will create .meta files inside the package: commit them. Open it (unity open) and read the Console.
3. FIRST THING TO FIND OUT: does the package compile under Unity 6? Its Runtime/*.cs have only been compiled by dotnet as C# 9 on .NET Standard 2.1. Report every error and warning verbatim. Fix real incompatibilities in the C# (smallest change), keep dotnet test passing (dotnet test unity/Packages/com.mira.stage/Tests~/Tests/Mira.Stage.Tests.csproj; 165 tests when this was written, the live ones need node and pnpm install) and say what you changed. Then add an EditMode test in the Unity project that replays unity/Packages/com.mira.stage/Tests~/golden/locators.json through AssetLocator.Validate (case format: l or lu = UTF-16 code units, r = none|win|posix, h = allowed hosts, ok, kind, n) and run it with unity test: the locator port relies on string.Normalize, which Unity's runtime must prove it can do.
4. Live control. Add com.unity.pipeline (unity pipeline install), reopen the project, confirm unity status is "ready".
5. UniVRM. Read https://vrm.dev (the UniVRM 1.0 install and runtime import pages) and install the VRM 1.0 packages by git URL at a release that supports Unity 6, after telling me the exact URLs and tag. Do not guess a version.
6. The Unity layer, in unity/Packages/com.mira.stage/Runtime/Unity/ with its own asmdef Mira.Stage.Unity (references Mira.Stage and UniVRM; the existing Mira.Stage asmdef has noEngineReferences and must stay that way). Requirements:
   - EVERY callback of IStageHandler arrives on a background thread. Build a main-thread bridge (a dispatcher drained in Update). HandleAsync must complete its Task only AFTER the Unity work is done, because commands are acknowledged in order and the daemon waits (it sends an utterance's audio only after perform.speak is acknowledged).
   - A MonoBehaviour that builds StageClientOptions (credentials via StageCredentialsResolver; Capabilities: engine unity, Application.unityVersion, rigFamilies ["vrm1"]; PerfProvider with fps, GPU ms, VRAM), runs StageClient.RunAsync, stops it on destroy and shows the state (Connecting, Connected, Refused 401/403/409) in an on-screen label.
   - A handler deriving from StageHandlerBase (see HeadlessStageHandler.cs for the exact semantics each command needs: asset.loaded / asset.failed BEFORE the command's done, camera and lighting checks, utterance bookkeeping).
   - character.load: resolve the base asset with StageContent.Resolve(MIRA_CONTENT_DIR, locator); load the VRM at run time with UniVRM (VRM 1.0 only; refuse VRM 0.x and other rig families with Fail). It must SUCCEED whenever the base model loads. Equipped assets that have no file (the seed wardrobe: wardrobe/crisp-shirt and so on) get asset.failed with a plain reason and an empty slot, and the command still completes: a failed character.load makes the daemon treat her as not loaded, so she would never perform. (A VRoid export already wears its own clothes, which keeps the clothed baseline.) Two characters exist: role assistant and role user.
   - scene.load: environments/cerebral-void is not a file: it is the room you build in the project (dark void, soft key and rim light, a little fog or particles; see docs/CEREBRAL-SPACE.md and the Atmosphere and LightingPreset fields) registered under that name. scene.camera: the six camera ids of the scene with blendMs; scene.lighting: map the preset to the lights.
   - Speech: perform.speak announces an utterance; audio arrives as binary frames (pcm_s16le, mono, 24 kHz, about 20 ms) tagged with the utterance hash, face weights as 52 ARKit floats per frame at 30 fps. Play the audio through an AudioSource from a ring buffer (a streaming AudioClip or OnAudioFilterRead), call Sink.SpeakStarted when playback really starts and Sink.SpeakEnded(id, interrupted) when it ends or perform.cancel fades it out. Drive the face from the audio clock (not wall time) so mouth and sound stay together; read packages/stage-core/src/speech/pipeline.ts for how the daemon times the frames.
   - Face and mood: build the map once per model with Vrm1Expressions.Build(the model's expression names) and apply it each frame with ExpressionMap.Apply; the baseline mood from perform.affect through Vrm1Expressions.FromAffect, blended over blendMs, combined with the face by the larger weight. These rules were never looked at on a face: tune them, and tell me what you changed. Confirm on screen that lookLeft/lookRight go the right way.
   - perform.gaze (user, camera, point, away), perform.idle (a small procedural breathing and sway per profile) and perform.posture stand: implement. perform.gesture: answer Fail("no gesture clips yet") rather than pretending. Anything else the Unity stage does not do must answer Fail with a plain reason (the contract's honesty rule; the daemon shows it in Settings, Stage).
7. Editor/BuildScript.cs: public static class Builder with PerformBuild that builds a Windows 64-bit player into unity/MiraStage/Build (git-ignored) and exits non-zero on failure, so that unity build unity/MiraStage --editor-version <v> --target StandaloneWindows64 --execute-method Builder.PerformBuild works from the command line. Run it once and report the result.
8. Prove it, in this order, and report each with what you saw: (a) Play mode connects, Settings, Stage in the browser shows the stage connected and the engine as unity; (b) both characters and the room appear (screenshot); (c) send a chat message in the browser: she answers with audio, her mouth moves with it, speak.ended arrives (the browser shows the utterance finishing); (d) kill the daemon and start it again: the stage reconnects by itself and is given the look again; (e) a wrong token shows Refused 401 on screen and does not crash.
9. Measure and report numbers, not adjectives: connect time; frames per second at 2560x1440 with one character and the room (Game view or the built player); GPU ms and VRAM from the perf events; the audio-to-lip offset you measured and how; the time from character.load to character visible. The gates from ADR 0008: 60 fps at 1440p, outfit swap under 1 s (not testable until wardrobe files exist: say so), audio to lip under about 120 ms.
10. Finish with: a table of what you verified (and how), a list of what is NOT verified, the three biggest risks you see for this route, and the one thing you would do next. Save the same text to spikes/unity/results/RESULTS.md. Commit your work on unity-stage-pc (code only) and tell me the branch and the commit list; do not push.
````

## Notes for the person who started the session

- It asks before every download, install and push. Say no to anything you do not understand.
- It does not need the real Claude: the backend runs with the fake Claude (scripted replies, no tokens). Type any ordinary message in the browser chat (for example: what is on my calendar today?) to trigger a spoken answer; words like send, delete or spend trigger approval cards in the fake Claude instead.
- No model ships with the repository. If you have none yet, VRoid Studio makes a VRM 1.0 file for free; check the licence of anything you download.
- Bring the pasted results back to the cloud session so the docs can be updated with real numbers.
