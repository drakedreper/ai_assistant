# Research digest: critic

Status: digest of the skeptical reviewer that cross-checked the seven research outputs and spot-verified the riskiest claims. Date: 2026-10-31. This is the most authoritative of the eight digests because it resolves conflicts between the others. Hosts the critic could not reach (developers.google.com, support.google.com, live2d.com direct pages, learn.microsoft.com, open-meteo.com, newsapi.org, gnews.io, huggingface.co, vroid.com, ollama.com, arxiv.org) mean some Google, Microsoft and licence facts rest on search excerpts and secondary sources.

## Question

Where do the research outputs contradict each other, which headline claims survive a spot check, what licence or terms risks exist, what is missing, what should be cut, and what single integrated stack follows?

## Licence and terms risks

| Area | Risk |
|---|---|
| Anthropic terms (verified) | SDK use falls under the Commercial Terms; third parties may not offer claude.ai login or rate limits or intermediate credentials; plan limits assume ordinary individual usage, so a 24/7 daemon on a subscription is a grey zone; API keys for everything the daemon launches is the clean path |
| Branding (verified) | "Claude Code" or "Claude Code Agent" may not be in a product name, and a product must not mimic Claude Code's look; "Claude Agent" or "<YourName> Powered by Claude" are allowed |
| Consumer versus Commercial terms | Both exist (verified); data-use differences are from memory and need checking before email, finance and companion conversations flow through a subscription |
| Live2D | Cubism Core is proprietary; avatar systems are excluded from the small-scale exemption; fine for a private unreleased app, blocks distribution; VRM avoids it |
| VRM models | Each carries its own licence (separate commercial, corporate, political and antisocial-use fields in VRM 1.0 exports); Booth models prohibit redistribution; a sexual-expression flag exists (from memory, unverified); an original design avoids cloning IP |
| TTS and voice | Kokoro Apache-2.0 (safe); F5-TTS weights CC-BY-NC; XTTS-v2 weights non-commercial; Piper GPL-3.0; Chatterbox watermarks output; ElevenLabs' free tier is evaluation only; cloning a real person's voice raises consent issues; cloud TTS sends every sentence to a third party |
| Embedding model | EmbeddingGemma is under the Gemma Terms of Use (use restrictions flow down; not OSI): fine locally, review before redistribution |
| Copyleft or no-licence code (do not copy) | opcode (AGPL-3.0), claude-squad (AGPL-3.0), SillyTavern (AGPL-3.0), Mate-Engine (AGPL-3.0 plus custom), Utsuwa (AGPL-3.0-or-later after v0.12.0), Basic Memory (AGPL-3.0), Firefly III (AGPL); disler hooks repo (no LICENSE file); Open-LLM-VTuber frontend (commercial-restricted). Safe with attribution: CCAM, claude-view, ccusage, AIRI, three-vrm, Amica, vibe-kanban (Apache-2.0). `dockview-enterprise` is proprietary; use `dockview-react` (MIT) only |
| Data-source terms | Open-Meteo free for non-commercial use with CC BY 4.0 attribution (server code AGPL, not embedded); NewsAPI free tier is development-only; GNews free tier is non-commercial and delayed; publisher RSS terms vary (keep headline, link, short snippet); free market-data tiers change often |
| Google platform | An unverified "In production" app is fine for one user; Gmail restricted scopes need verification and an annual CASA assessment if distributed; "Limited Use" rules on passing Google user data to third-party AI services are from memory and unverified |
| Telemetry and egress | MediaPipe Tasks send usage metrics to Google by default; Claude Code OTel attributes include `user.email`; claude-view official builds send anonymous telemetry; images and email bodies sent to Claude go to Anthropic under the chosen auth's terms |
| Third-party and biometric data | The webcam can capture other people and face landmarks are biometric-adjacent; if the user is in the EU or Nordics (a hint, not confirmed) GDPR duties may apply; the household exemption probably covers a purely personal tool, but this is a question to settle |
| Windows distribution | SmartScreen and code signing matter only if an installer is shared; Tauri's updater signing key is mandatory if Tauri is chosen |

## Gaps (what nobody covered)

1. Testing strategy for the Linux sandbox versus Windows target gap. Needed: a Windows CI runner, Playwright against fixtures, a fake Claude transport, recorded hook payloads and roster outputs, provider contract tests, a retrieval eval set, a latency harness, persona golden conversations, and a Phase 0 spike on the real PC. See [ARCHITECTURE.md](../ARCHITECTURE.md) section 12.
2. Backup, recovery and export: encrypted offsite backup, SQLite backup API, a restore drill, no OneDrive-style synced vault, migration and versioning. See ARCHITECTURE section 13.
3. Cost control with no single owner: a daemon-level budget service, `maxTurns` on every session, 429 handling, image-token budgeting, prompt-cache hygiene, a visible spend chip. See ARCHITECTURE section 15.
4. Privacy and data-flow policy: a map of what leaves the machine, sensitivity labels, redaction, an audit log, on-demand raw data, a local-model fallback idea, redaction of hook payloads, the conflict between "forget" and a git-versioned vault. See [PRIVACY.md](../PRIVACY.md).
5. Offline and degraded behaviour. See ARCHITECTURE section 14.
6. Persona safety and boundaries (named as a risk, never specified). See [PERSONA.md](../PERSONA.md).
7. Windows specifics checklist (Defender, file locking, path limits, backslash paths in hook payloads and deny rules, Git Bash versus PowerShell, sleep, orphaned processes, user-session app, camera exclusivity, echo cancellation, GPU contention, RAM budget, SmartScreen). See ARCHITECTURE section 11.
8. Product and UX definition of the mockup: information architecture, art direction, design tokens, "second brain first, not a calendar overview" home screen, interruption budget, accessibility, language. The mockup and PERSONA.md address these.
9. Second-brain integration seams: how session summaries become notes, who is the single writer with Obsidian open, how Secondbrain relates to the new vault, importing an existing vault, note language.
10. App observability and supply chain: redacted structured logs, a health endpoint, crash-restart supervision, a diagnostics bundle, pinned and contract-tested upgrades, dependency and licence scanning in CI.
11. Unverified hosts: the Google, Microsoft, Live2D, Open-Meteo, NewsAPI, GNews, Hugging Face, VRoid, Ollama and arXiv pages need allow-listing to close facts the design depends on.

## Suggested scope cuts

1. Speech: text chat first, then TTS, then push-to-talk STT, then VAD. Cut wake word, hands-free barge-in, Smart Turn, viseme lip-sync and speech-to-speech.
2. Avatar: one VRM 1.0, three to five VRMA clips, procedural blink and look-at, five emotion presets, a simple room. Cut Live2D, custom models, outfits, weather particles, raycast-clickable props and camera parallax. Cap at 30 fps and pause when hidden.
3. Webcam: an explicit "look at this" snapshot; local MediaPipe presence later; no continuous frames and no mood inference.
4. Dashboard: session grid, status state machine, timeline, approval cards, subagent tree and a basic cost chip. Cut OTel, statusline receiver, config explorer, cost per commit, heatmap, remote sync, mobile PWA, worktree workspaces, checkpoints, other-agent adapters. Kanban is manual cards linked to `session_id`.
5. Second brain: vault skeleton, flat frontmatter, FTS5, the `brain_*` tools, a CodeMirror 6 editor with backlinks, a proposals queue, nightly digest and weekly review. Defer sqlite-vec until the eval shows FTS misses; defer the sigma graph, JSON Canvas, `.base` parsing, bi-temporal facts, importance-sum triggers, WYSIWYG editing, qmd and LLM rerank.
6. Integrations: mocks first, then RSS, Hacker News and Open-Meteo, Google Calendar read-only, Gmail read-only, Contacts. Cut Microsoft Graph, CalDAV, CardDAV, IMAP, GDELT, Wikipedia, USGS, market data, NewsAPI, GNews and all write actions until read paths and approval UX are proven. Atlas: contract, mock and contract tests only.
7. Shell and packaging: browser-first; cut installer, auto-update, signing, Tauri, WSL 2 sandboxing, remote access, Bun-compiled daemon, `node:sqlite` and Drizzle 1.0-rc. Fixed CSS-grid layout with the Room at about 25 percent; dockview presets later.
8. Claude lanes: exactly one Secretary session plus the tool-less briefing call; a separate Voice lane only if the TTFT gate fails; no subagent specialists, daemon-spawned worker sessions or multi-model routing in the MVP.
9. Repo shape: `apps/web`, `apps/daemon`, `packages/shared` first; one mock mechanism (in-app fixtures or MSW), no TypeSpec, Prism and MSW stack, no OpenAPI codegen.
10. Mockup deliverable: a Vite and React fixtures app (or a single static page) with fake data and a looping VRM or 2D image in the Room pane, built in one to three days; do not build the daemon or a Rust shell for it.

## Integrated stack recommendation (summary)

- Auth: API key for everything the daemon starts; observe terminal sessions; never touch OAuth tokens; no connectors; one email to Anthropic; the switch stays so subscription use needs no architecture change.
- Shell: browser-first through Phase 2; a thin Electron shell later (pin 45.x); daemon separate on plain `node.exe`; the shell only supervises, adds tray, autostart and single-instance, and injects the token.
- Frontend: React 19, Vite, TypeScript strict, Tailwind 4 with shadcn, Zustand plus TanStack Query fed by the WebSocket, `@dnd-kit/core`, Recharts; a fixed CSS grid with the Room at about 25 percent; `dockview-react` (MIT) only in Phase 2 or later.
- Daemon: Node 24 LTS or 26, TypeScript, Hono, a typed WebSocket envelope with `seq`, zod shared with the UI; loopback only, Host and Origin validation, per-install token, strict CSP, sanitised model and email HTML, logged approvals; three packages first.
- Claude layers (all TypeScript Agent SDK, pinned): Secretary (one long-lived streaming session with a cached persona and digest prefix, `settingSources:['project']`, auto memory off, connectors disabled, a programmatic `SessionStart` hook, in-process MCP tools, `canUseTool`, `interrupt()`); Voice (only if Phase 0 requires it: direct Messages call to Haiku 5.5 at low effort); Reader (tool-less, schema-constrained, separate from any session with send, write or finance tools); dream and triage jobs over untrusted inbox content may only propose or quarantine.
- Monitor: user-level `http` hooks to `127.0.0.1` with a bearer token on non-blocking events only; `claude agents --json --all` for the roster (`state` and `id` are background-only); SDK history; for daemon sessions ingest the SDK stream and dedupe hook events; a staleness timer; cost labelled "API-equivalent estimate"; OTel later.
- Data: an ops SQLite (better-sqlite3 13 with Drizzle 0.45) with an append-only raw events table; the vault as Obsidian-compatible markdown with flat frontmatter and wikilinks, git-versioned and backed up; a derived index (FTS5 first, sqlite-vec later behind `VectorStore`); CodeMirror 6; secrets in `@napi-rs/keyring`; croner with catch-up and per-job budgets.
- Avatar and voice: three plus `@pixiv/three-vrm` 3.5.x on WebGL, a licence-checked VRM 1.0, a low-poly GLB room, a behaviour state machine bound to daemon events, a closed emotion-tag set stripped before TTS, amplitude lip-sync; voice order text, TTS behind `TtsProvider`, push-to-talk STT with whisper.cpp as a managed child process, then `@ricky0123/vad-web`, headphones until echo cancellation is proven; webcam through local MediaPipe with self-hosted assets and frames to Claude only on request.
- Integrations: provider interfaces with mocks first; Google desktop OAuth in the daemon; Calendar read-only, then Gmail read-only; RSS, Hacker News and Open-Meteo need no keys; the Atlas contract with signed minor-unit money and cursor sync, mock and contract tests; resolve the Secondbrain and Atlas naming and overlap questions with the user.
- Phase 0 spikes (one to two days on the real PC, as release gates): TTFT through a persistent SDK session versus a direct Messages call; `http` hooks from Windows Claude Code reaching the daemon including a daemon-down test; Electron WebGL, `getUserMedia`, whisper.cpp and Kokoro latency on the actual GPU and in the user's language; the Anthropic terms email. Then the clickable mockup, Phase 1 text chat plus monitor, Phase 2 vault and read-only integrations, Phase 3 the shell, voice and webcam. (The approved plan numbers these slightly differently: see [PLAN.md](../PLAN.md).)
