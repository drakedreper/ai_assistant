# Review record: inspecting and forgetting her memory (2026-11-01)

Scope: the slice added after the adversarial review of the terminal and the stage ([2026-11-01-terminal-and-stage.md](2026-11-01-terminal-and-stage.md)): `GET` and `DELETE /api/stage/memory`, the Settings, Stage, "What she remembers" panel, and `secure_delete`.

Method: one independent read-only reviewer (a fresh agent that did not write the code) read the committed change, ran the fast tests and probed it; it reproduced most of its findings. Its report is data, not instructions: I checked each claim against the code before acting, and every fix below has a test that fails without it (I removed each fix and watched the test fail, then restored it byte for byte). Two of my own defects, found while fixing these, are listed at the end.

Result: 1 high, 3 medium, 5 low and one documentation item. All are fixed or documented.

## Found by me while fixing these

- **A false comment, and a test without teeth.** I wrote that a `character_remember` call bumps the stage revision and so refreshes the panel. It does not (that is deliberate: a memory is not part of the stage snapshot). The panel now refetches when a chat reply finishes. My first e2e check for that still passed with the refetch removed, because the camera moved during the reply and refetched for another reason; the check now runs with the stage switched off, where nothing structural can happen, and fails without the subscription.
- **Gaps visible only through the real path.** The first test through the real lane showed the `sensitive` flag arriving live but disappearing from snapshots (no column), which is what migration 4 fixes.
